# 生成复盘数据包

## 核心原则

只运行仓库已有的稳定入口 `scripts/review_data_pack.py`。不得生成或改写 SQL，不得修改现有文档；正式模式只创建一份新的飞书表格。

## 工作流

1. 从用户消息中识别四项必填输入：`活动名称`、`开始日期`、`截止日期`、`活动目标`。只询问缺失项；不得索取策略来源期或其他可选参数。若用户只说“生成复盘数据包”且缺少四项，只列出缺失项并等待回复。
2. 把日期规范为 `YYYY-MM-DD`。计算活动期和整体向前平移一年的同比期；日期无法保持相同月日时停止并说明。运行前回显：

   ```text
   活动期：YYYY-MM-DD ~ YYYY-MM-DD
   同比期：YYYY-MM-DD ~ YYYY-MM-DD
   ```

3. 按用户措辞选择模式，不额外询问：

   - 用户明确说“预演”“测试”或“演示”时，使用预演模式：追加 `--sample --dry-run`。这是示例数据，只验证流程，不查询真实结果，也不创建飞书表格。
   - 其他情况使用正式模式：不追加 `--sample` 或 `--dry-run`。

4. 正式写入前依次运行 `command -v lark-cli` 和 `lark-cli auth status --json --verify`。仅当 lark-cli 已安装且用户身份为可用、已验证状态时继续；不得展示认证输出或令牌。预演模式不要求飞书认证。
5. 在仓库根目录运行且只运行以下稳定命令；不要补写 SQL，不要直接调用数据库或飞书写入命令：

   ```bash
   PYTHONPATH=src python3 scripts/review_data_pack.py \
     --name "<活动名称>" --start "<开始日期>" --end "<截止日期>" \
     --target "<活动目标>" [--sample --dry-run]
   ```

6. 前台等待命令结束并解析其唯一 JSON 输出。命令未退出前不得宣称完成。以输出中的 `current_period`、`last_year_period`、`modules`、`check_summary`、`failed_modules`、`configuration_errors` 和 `lark_url` 为准，不从日志猜测结果。运行前的日期回显不属于结束结果；正式模式结束时不得重复日期或增加其他字段。

## 结果合同

### 正式模式

无论成功或失败，只汇报且必须恰好汇报以下三项。不得增加第四项，不得在模板前后另起错误说明、恢复建议、日期、逐指标结果、运行日志、本地路径或实现过程：

```text
飞书链接：<lark_url；没有生成则写“未生成”>
检查摘要：<通过 passed；警告 warning；失败 failed；若未执行则写“未执行”>
失败模块：<无；或模块名、必要错误类型和恢复建议>
```

飞书预检、输入校验、数据执行、飞书写入或回读中的任何失败都使用同一模板：链接写“未生成”；已有检查数字照常填写，没有则写“未执行”；把必要的错误类型和恢复建议压缩进“失败模块”的值中。不得另起字段或段落。

### 预演模式

预演结果使用以下形状：

```text
示例数据预演：不是实际活动结果，未创建飞书表格
活动期：<current_period>
同比期：<last_year_period>
检查摘要：<通过 passed；警告 warning；失败 failed>
失败模块：<无；或模块名及简短原因>
```

不得把示例数据表述为真实结果，也不得把示例模块成功表述为正式模块成功。

未知活动若缺少定金或蓄水策略来源期，把对应模块写入“失败模块”，并依据 `configuration_errors` 标为“配置缺失/不适用”；不得把它改写成指标为零、查询失败或策略模块成功。

## 快速检查

| 情况 | 动作 |
|---|---|
| 缺少四项中的任一项 | 只询问缺失项 |
| 明确要求预演 | 使用 `--sample --dry-run` 并标注示例数据 |
| 正式运行 | 先检查 lark-cli 安装与用户认证 |
| 缺少策略来源期 | 标为配置缺失/不适用，不虚构结果 |
| 命令完成 | 按结果合同汇报 |

## 常见错误

- 自行生成 SQL 或绕过稳定脚本。
- 为未知活动追问策略来源期，而不是让既有配置检查明确暴露不适用模块。
- 用预演数据回答实际营收、转化或模块成败。
- 正式模式输出完整 JSON、大段指标或三项合同以外的说明。
- 修改或覆盖已有飞书表格、复盘文档或仓库文档。
