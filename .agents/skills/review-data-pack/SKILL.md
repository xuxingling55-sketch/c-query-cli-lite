# 生成复盘数据包

## 核心原则

只运行仓库已有的稳定入口 `scripts/review_data_pack.py`。不得生成或改写 SQL，不得修改现有文档；正式模式只创建一份新的飞书表格。

## 工作流

1. 从用户消息中识别四项必填输入：`活动名称`、`开始日期`、`截止日期`、`活动目标`。只询问缺失项；不得索取策略来源期或其他可选参数。若用户只说“生成复盘数据包”且缺少四项，只列出缺失项并等待回复。
2. 把日期规范为 `YYYY-MM-DD`。计算活动期和整体向前平移一年的同比期；日期无法保持相同月日时停止并说明。运行前回显：

   ```text
   活动期：YYYY-MM-DD ~ YYYY-MM-DD
   同比期：YYYY-MM-DD ~ YYYY-MM-DD
   ```

3. 按用户措辞选择模式，不额外询问：

   - 用户明确说“预演”“测试”或“演示”时，使用预演模式：追加 `--sample --dry-run`。这是示例数据，只验证流程，不查询真实结果，也不创建飞书表格。
   - 其他情况使用正式模式：不追加 `--sample` 或 `--dry-run`。

4. 正式写入前依次运行 `command -v lark-cli` 和 `lark-cli auth status --json --verify`。仅当 lark-cli 已安装且用户身份为可用、已验证状态时继续；不得展示认证输出或令牌。预演模式不要求飞书认证。
5. 在仓库根目录运行且只运行以下稳定命令；不要补写 SQL，不要直接调用数据库或飞书写入命令：

   ```bash
   PYTHONPATH=src python3 scripts/review_data_pack.py \
     --name "<活动名称>" --start "<开始日期>" --end "<截止日期>" \
     --target "<活动目标>" [--sample --dry-run]
   ```

6. 前台等待命令结束并解析其唯一 JSON 输出。命令未退出前不得宣称完成。以输出中的 `current_period`、`last_year_period`、`modules`、`check_summary`、`failed_modules`、`configuration_errors` 和 `lark_url` 为准，不从日志猜测结果。运行前的日期回显不属于结束结果；正式模式结束时不得重复日期或增加其他字段。

## 结果合同

### 正式模式

无论成功或失败，只汇报且必须恰好汇报以下三项。不得增加第四项，不得在模板前后另起错误说明、恢复建议、日期、逐指标结果、运行日志、本地路径或实现过程：

```text
飞书链接：<lark_url；没有生成则写“未生成”>
检查摘要：<通过 passed；警告 warning；失败 failed；若未执行则写“未执行”>
失败模块：<无；或模块名、必要错误类型和恢复建议>
```

飞书预检、输入校验、数据执行、飞书写入或回读中的任何失败都使用同一模板：若输出已有 `lark_url`，必须原样填写该链接；只有没有 `lark_url` 时才写“未生成”。回读失败但 `lark_url` 已返回，说明表格已经创建，必须保留该链接并提示验证已有表格，不得重跑创建。已有检查数字照常填写，没有则写“未执行”；把必要的错误类型和恢复建议压缩进“失败模块”的值中。不得另起字段或段落。

### 预演模式

预演结果使用以下形状：

```text
示例数据预演：不是实际活动结果，未创建飞书表格
活动期：<current_period>
同比期：<last_year_period>
检查摘要：<通过 passed；警告 warning；失败 failed>
失败模块：<无；或模块名及简短原因>
```

不得把示例数据表述为真实结果，也不得把示例模块成功表述为正式模块成功。

未知活动若缺少定金或蓄水策略来源期，把对应模块写入“失败模块”，并依据 `configuration_errors` 标为“配置缺失/不适用”；不得把它改写成指标为零、查询失败或策略模块成功。

## overview 模块口径（2026-07-28 起）

- 渠道业绩营收：订单表正价实付（`original_amount >= 39` 的订单 `sub_amount`，剔除测试用户，按 `business_gmv_attribution` 归属渠道）。
- 服务期营收：按**服务期团队归属**统计（`correct_team_names` 含 商业化-APP 记 APP、含 电销/网销 记销售），不限制订单的 GMV 渠道归属。方向自检：电销服务期应高于其业绩营收（承接其他渠道订单的服务期）、APP 相反；两者近似相等说明口径错了。
- 转化类指标（active_efficiency 等模块）来自活跃表正价付费口径，与 overview 的订单口径绝对值不可互算。

## APP 渠道专项指标（数据包未覆盖，需专项补查）

以下指标族不在 `review_data_pack.py` 的 8 个模块内，本 skill 不负责取数。复盘需要 APP 渠道归因时，先问用户是否已有 APP 专项复盘文档；没有再按下列口径补查（口径沿用 2026.7 APP 营收问题诊断复盘）：

| 指标族 | 关键指标 | 口径要点 |
|---|---|---|
| 营销页漏斗 | 进入用户、覆盖率、商品点击率、当日购买率、承接组合品 GMV | 两种口径并报：用户日（每活跃/进入一天计一次）与累计去重（区间内同一用户只计一次）；支持分学段、分用户层 |
| 直播间漏斗 | 场次、进房 UV、人均观看时长、评论人数/率、购物车点击率、商品点击率、进房至支付率、支付 GMV、客单价 | 按直播间目标学段拆（小学/初中/高中/小初/小初高）；直播归属用 sell_from 识别 |
| 场景拆分 | 直播 vs 非直播 GMV、组合品分场景 | 用于回答“缺口发生在哪个场景”；直播+非直播应可加总回 APP 合计 |
| 价格带对比 | 198 vs 498 订单量与 GMV | 用于评估低门槛需求承接率（如 498 增量 / 198 减少额） |
| 商品与购买类型 | 零售/组合品/续购/其他；组合品按小学品/初中品/高中品/小初品/小初高品；首购 vs 续购 | 数据包 product_structure 只有粗分类，学段品和首购/续购交叉需专项 |
| 学段电销占比 | 学段内电销营收占比 | 用于判断服务期电销倾斜是否放大 APP 降幅 |

**口径警示**：APP 专项常用“GMV 不加正价限制”，与数据包的正价营收口径不同，两边绝对值不可直接相加或互相校验；引用时必须标注区间和口径。

## 快速检查

| 情况 | 动作 |
|---|---|
| 缺少四项中的任一项 | 只询问缺失项 |
| 明确要求预演 | 使用 `--sample --dry-run` 并标注示例数据 |
| 正式运行 | 先检查 lark-cli 安装与用户认证 |
| 缺少策略来源期 | 标为配置缺失/不适用，不虚构结果 |
| 要直播/营销页/场景/价格带数据 | 不在 8 模块内，按“APP 渠道专项指标”清单引导专项补查 |
| 命令完成 | 按结果合同汇报 |

## 常见错误

- 自行生成 SQL 或绕过稳定脚本。
- 为未知活动追问策略来源期，而不是让既有配置检查明确暴露不适用模块。
- 用预演数据回答实际营收、转化或模块成败。
- 正式模式输出完整 JSON、大段指标或三项合同以外的说明。
- 修改或覆盖已有飞书表格、复盘文档或仓库文档。
