# 活动复盘

从"活动结束"到"一份能对外同步的复盘报告"的完整流程。核心产出是判断，不是数据：每个环节都要回答"所以呢"。

## 硬约束

1. **所有数字必须有出处且可复现**：来自复盘数据包、仓库既有报告/CSV，或按 `knowledge/AI提示词.md` 口径新查的数据。禁止编造或从记忆里估数；引用早期草稿或往期结论里的数字前，先从数据包或 SQL 复现一遍，复现不了就以可复现的数字为准并在报告中注明修正。
2. 新写 SQL 时严格遵循 `knowledge/` 口径（正价营收、活跃主表、去重规则等），先读 `knowledge/AI提示词.md` 再动手。
3. 报告落在 `reports/YYYYMMDD_<活动名>_复盘.md`。如需同步到飞书文档/多维表格，先问用户建在工作号还是个人号下。

## 口径规范（报告全文统一，附录写清）

- **营收类**（营收卡、渠道营收、目标完成率、同比缺口）：订单表正价实付口径——`dws.topic_order_detail` 中 `original_amount >= 39` 的订单 `sub_amount`，按 `business_gmv_attribution` 归属渠道（商业化=APP、电销=销售），剔除测试用户。
- **服务期营收**：按**服务期团队归属**统计（`correct_team_names` 含 商业化-APP 记 APP、含 电销/网销 记销售），**不限制订单的 GMV 渠道归属**，正价实付筛选同上。电销团队承接其他渠道订单的服务期，方向自检：电销服务期应高于其业绩营收、APP 相反；若算出"服务期≈业绩"或方向反了，说明误按订单渠道分组，停下来核对。
- **转化类**（付费转化率、ARPU、客单价及全部分层/学段/商品拆解）：活跃表正价付费口径——`aws.business_active_user_last_14_day` 的 `normal_price_amount`，付费用户须来自活跃池。分层拆解的"营收/付费金额"保持活跃口径，与转化率同源自洽，不与营收卡混算。
- 两套口径绝对值不可直接互算。
- **口径不进主文档**：所有口径定义、数据来源细节、已知限制与修订记录，单独成一篇「[口径]xxx · 指标口径与修订记录」飞书文档（新建前先问工作号还是个人号）；主复盘文档正文和附录只放 cite 引用，不出现口径解释、SQL 字段名或"该算法已修正"类表述。本地工作稿的附录可保留口径细节。

## 工作流程

### 第 1 步：确认复盘框架

需要四项必填输入，缺什么问什么：活动名称、活动期（起止日期）、活动目标、报告读者（管理层同步还是业务复核，决定详略）。

同时主动追问一项可选材料：**是否有活动方案、阶段复盘、复盘会议纪要/妙记、会议待办或渠道专项复盘文档**。有则请用户提供链接或文件；没有不阻塞取数。不能因为用户没主动提，就跳过询问。

**活动目标必须逐项确认，不能只拿一个总数就开工**。正式复盘模板的营收卡需要以下目标位，用户只给了总目标时要反问其余各项：

1. 业务营收总目标（GMV 口径，不含服务期）
2. 服务期营收目标（口径不同，不能拿业务目标凑）
3. 分渠道子目标：销售、APP（模板需分渠道判断"是否达标"）
4. 激进/保守双目标位（如果本次设了两档）

用户明确回答"没设"的项，在报告中写"未设置"，不留空也不推算；用户没回答的项不能自行脑补或用总目标按比例拆。

同比期默认整体前移一年、保持相同月日。

### 第 2 步：取数

优先走 review-data-pack skill（稳定脚本 `scripts/review_data_pack.py`），一次取齐 8 个模块：

| 模块 | 回答的问题 |
|---|---|
| overview | 总盘：营收、订单、付费用户、同比 |
| active_efficiency | 活跃规模与活跃转化效率 |
| user_stage | 用户分层（新增/老未/续费/高净值）× 学段 |
| product_structure | 商品结构（零售/组合品/续购，首购/复购） |
| deposit / reservoir | 定金、蓄水策略效果（未配置则标不适用） |
| high_value | 高净值用户表现 |
| sales_funnel | 销售漏斗 |

数据包覆盖不了的问题（如直播间漏斗、营销页漏斗、单日趋势），按 knowledge 口径补查，并把口径记入报告附录。

### 第 3 步：目标达成评估

先回答三个问题，再进归因：

1. 目标完成了多少？（实际 / 目标）
2. 和去年同期比是多少？（同比缺口或增量的绝对额 + 百分比）
3. 缺口/增量的趋势是什么？（活动期内分段看，缺口在收窄还是扩大；单日反弹不算收窄）

### 第 4 步：归因

用固定的分解框架，避免东一榔头西一棒子：

**主公式**：营收 = 活跃用户 × 付费转化率 × 客单价。先算三个因子各自的同比，回答第一个大判断——**是流量问题还是效率问题**：

- 付费用户降幅 > 活跃降幅 → 效率问题（承接/转化），继续往商品和漏斗拆。
- 活跃降幅 > 付费降幅 → 流量问题，往渠道和获客拆。
- 客单价上涨不等于健康：必须同时看交易频次，"单笔更贵但单数腰斩"是价格门槛问题。

**四个拆解轴**，逐轴找缺口集中度（哪个切片占总缺口 50% 以上）：

1. 渠道：电销 / APP / 新媒体 / 智课 / 平台电商
2. 学段：小低 / 小高 / 初中 / 高中
3. 用户分层：新增 / 老未 / 续费 / 高净值
4. 商品结构：零售 / 组合品 / 续购；首购 / 复购；价格带

拆解时的判断准则（来自历史复盘的经验）：

- 每个轴拆完要下一句"问题不是 X，而是 Y"式的判断，不能只列数字。
- 增量项（如高净值增长）要算够不够对冲缺口，不夸大亮点。
- 池子缩小和效率下降要分开说（"续费转化率在涨但续费活跃池 -35%"是两件事）。
- 累计和边际分开看：活动后期单独开窗口（如最近三天），判断措施是否起效。

### 第 5 步：定性证据与动作闭环（可选但强烈建议）

数据说"发生了什么"，定性材料说"为什么"，阶段会议材料还能回答"当时怎么判断、后来有没有做到"。两类来源：

- 活动方案、阶段复盘、会议纪要 / 妙记、会议待办、渠道专项复盘中业务侧已有的判断与动作，引用时注明来源。若用户尚未提供，先问一句："有阶段复盘、复盘会议纪要/妙记或会议待办吗？有的话请发链接，我会核对当时判断和动作闭环。"
- 沟通录音：如果当前环境安装了 comms-dataprep 和 speaker-attribution-prep 技能，用它们圈人拉录音、标说话人后抽样分析未成交原因；没有这两个技能时，请用户直接提供录音文本或纪要材料，或跳过本步并在报告中注明。分析方法：先随机小样本（约 10 条）验证归类框架，再全量归类，每类原因给出证据条数。

定性结论必须和定量缺口对得上（如"低价入口减少"应对应零售订单量数据）。

拿到阶段复盘或会议纪要后，建立一张闭环核对表：

| 当时判断 / 风险 | 当时承诺动作 | 最终数据结果 | 闭环判断 |
|---|---|---|---|
| 原文摘录并注明来源 | 负责人、动作、预期（纪要有才写） | 用全周期数据验证 | 已验证 / 部分验证 / 未验证 / 数据不足 |

使用规则：

- 区分**会议预测**与**最终事实**，不能把"预计、乐观判断、目标"改写成已实现。
- 智能纪要可能不准确；涉及关键数字、负责人和承诺动作时，优先与原复盘文档、妙记原文或最终数据交叉核验。
- 报告至少回答：阶段风险后来是否发生、承诺动作是否执行、动作与结果是否存在可验证关联。不能仅把会议内容摘抄一遍。
- 有飞书正式文档时，用 `<cite type="doc">` 引用材料；附录列出定性证据来源。

### 第 6 步：结论与建议

复盘四问，写进报告开头的结论区：

1. 目标定得对不对？（结果和目标差多少，差异来自目标还是执行）
2. 什么做对了？（有数据支撑的亮点，说明可否复制）
3. 什么做错了 / 没做够？（缺口主因，按贡献排序）
4. 下次怎么办？（3 条以内可执行建议，每条对应一个归因结论）

### 第 7 步：成文

产出分两层，句子规则都遵循 report-polish skill：

**本地工作稿**（默认必产出）：写到 `reports/YYYYMMDD_<活动名>_复盘.md`，结构为一句话总结 → 先看结论 → 关键数字表 → 分析正文（每节"结论标题 + 证据 + 解读"）→ 附录（口径、数据来源、数据包链接）。

**飞书正式复盘文档**（用户要求同步时产出，先问工作号还是个人号）：不套工作稿结构，按团队正式复盘模板组织（参照往期范例 [2025.7 冲顶暑促私域业务复盘](https://guanghe.feishu.cn/docx/B1EQd91NZoGKgjxiSjgcF5G0nye)）：

1. **顶部"营收完成情况"区**：callout 只放一句总判断（GMV/服务期完成率 + 缺口归属渠道 + 同比方向），数字明细放 callout 外的两张小表——GMV 完成情况、服务期完成情况，列固定为「渠道 | 营收 | 目标 | 完成率 | 目标缺口 |（同比）」，每渠道一行。注意飞书 callout 内不支持表格，表格必须放 callout 外面。有激进/保守双目标就都列。
2. **一、私域经营分析**：
   - 总判断 callout：首句一句话结论，随后 3 个 bullet 拆分——量价结构（主公式 活跃 × 转化 × 客单 → ARPU → 营收）、缺口归属（同比缺口与目标缺口分开说，两者常不同源）、目标松紧（渠道目标相对去年实际的高低）。
   - ‼️关键信息‼️三段 callout：**正向收益**（🤗）、**负向影响**（🤯）、**需要特别关注**（❗）。每条一行结论 + 1~2 个支撑数字，细节推导放对应章节并写"详见「X、xx 分析」"；每条尽量量化营收影响，亮点要说明可否复制，风险要区分一次性还是趋势性。
   - **讨论区 callout**（🗣️）：3~5 个开放问题供管理层会上讨论，每个问题带数据依据，不给结论。
   - **首周会议判断与动作闭环表**（有阶段复盘/会议纪要时）：放在本章讨论区 callout 之后、详细数据之前，不放渠道章——闭环覆盖全渠道，前置能让读者带着"哪些已预警"读后文。
   - 详细数据：**嵌入文档的数据表必须先加工，禁止直接嵌数据包的原始取数长表**（几百上千行的长表在文档里不可读）。参照范例格式做成汇总宽表：指标为列，每个分组（渠道/用户层/学段/商品）固定四行——本期、去年同期、同比（相对变化）、同比（绝对变化）；金额千分位、比率保留两位小数、绝对变化的比率用 pp。**表格内不放口径尾注**，各表口径与快照时间集中写进口径文档的「嵌入汇总表说明」一节。做法是在数据包同一个飞书表格里新建「XX-汇总」工作表写入加工结果并嵌入文档，原始明细工作表保留不动。聚合长表时注意：按渠道过滤避免跨渠道双算，用户层聚合不含高净值子层（避免与高净值汇总双算），比率不能直接求和、须用分子分母重新计算。表标题统一编号为「表N：xxx」（h3 同级），没有数据的占位标题删掉、移入附录待补清单。
   - **每张表配业务视角的描述性统计**：表标题与嵌入表之间放一个引用块（blockquote），3~4 句讲清这张表的业务事实——总盘规模与方向、增量/缺口来自哪个分组、结构分化点（谁涨谁跌），数字带同比；只做描述不下判断（判断留给正文结论区），也不出现口径措辞。
3. **二、渠道分析**：销售、APP 各自的关键结论；有渠道专项复盘文档就用 cite 引用（区间/口径差异不在正文解释，指向口径文档）。与第一章重复的数字推导只保留一处，另一处引用。
4. **附：数据来源**：数据包链接、定性证据 cite、待补项清单，最后一条固定为"全部指标口径、嵌入表格加工规则、数据检查摘要与修订记录见 [口径文档 cite]"。口径解释本身不写在这里。

交付时向用户汇报：报告路径 / 文档链接、一句话总结（请用户确认判断）、数据上存疑待复核的点。

## 快速检查

| 情况 | 动作 |
|---|---|
| 缺活动名称/日期/目标/读者 | 只问缺失项 |
| 只有营收总目标 | 反问服务期目标、销售/APP 子目标、激进/保守目标位 |
| 未说明是否有阶段材料 | 主动询问活动方案、阶段复盘、会议纪要/妙记、会议待办或专项复盘；没有则继续 |
| 数据包模块失败或不适用 | 在报告附录如实标注，不虚构 |
| 要在文档里放数据表 | 先加工成汇总宽表（每组四行：本期/去年/同比相对/同比绝对），不嵌原始长表；表内不放口径尾注，表上方配业务描述引用块 |
| 数字对不上历史报告 | 停下来核对口径，标注差异原因 |
| 正文想解释口径 | 移入口径文档，正文只留 cite |
| 用户要发飞书 | 先问工作号还是个人号 |
| 只有单日改善 | 写"单日反弹"，不写"趋势收窄" |
