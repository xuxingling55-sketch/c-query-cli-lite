# 一键复盘数据包 Codex Skill 设计

## 1. 目标

在现有 `c-query-cli-lite` 项目中增加一个 Codex Skill。用户只需提供活动名称、开始日期、截止日期和目标值，系统即按固定指标清单一次取齐数据库数据，完成统一同比与一致性检查，并生成一份飞书复盘数据表格。

本产品首先解决两个问题：

- 当前复盘数据需要多轮问答才能补齐，容易漏项或使用不同时间范围。
- 同一指标在不同分析章节中可能出现冲突，人工需要反复核对并重组材料。

第一版只保证“数据一次取齐、口径统一、结果可核查”，不自动撰写会议结论，也不改动既有复盘文档。

## 2. 使用入口与输入

### 2.1 使用入口

入口为用户已经在使用的 Codex 对话。Skill 提供清晰、稳定的触发语义，不要求用户记忆复杂命令。

示例：

```text
生成复盘数据包：暑促，2026/7/1–7/15，目标 1.2 亿
```

### 2.2 必填输入

- 活动名称
- 本期开始日期
- 本期截止日期
- 活动目标值

### 2.3 自动推导输入

- 去年同期：将本期日期整体向前平移一年，保持相同起止月日和相同天数。
- 报告标题：`<活动名称>_复盘数据包_<开始日期>_<截止日期>`。
- 渠道范围：私域整体、APP、销售。

如果遇到闰日或业务日历无法一一平移，Skill 必须在执行前说明拟采用的去年同期日期；不能静默改变天数。

## 3. 输出

每次运行创建一份新的飞书电子表格，不覆盖历史结果。工作表按以下固定顺序排列：

1. `检查结果`
2. `经营总览`
3. `活跃效率`
4. `用户分层`
5. `学段表现`
6. `商品结构`
7. `定金策略`
8. `蓄水策略`
9. `高净值策略`
10. `销售承接`
11. `指标口径`
12. `运行记录`

每张业务表必须同时带出：

- 本期值
- 去年同期值
- 绝对变化
- 相对变化
- 本期日期范围
- 去年同期日期范围
- 口径标识
- 数据更新时间

百分比分母为零时显示为空并在检查结果中标记，不显示无穷或伪造的 0%。

## 4. 固定维度

### 4.1 渠道

所有核心模块同时输出三套数据：

- 私域整体
- APP
- 销售

### 4.2 用户分层

固定输出：

- 新增
- 老未
- 续费
- 高净值汇总
- 高净值－当年毕业
- 高净值－历史大会员可续购
- 高净值－历史大会员不可续购
- 高净值－其他组合品

用户分层以知识库确认的业务字段和枚举为准。若数据库出现未映射的新枚举，必须在检查结果中列为“未映射分层”，不能自动并入“其他”。

### 4.3 学段

固定输出：

- 1–3 年级
- 4–6 年级
- 初中
- 高中

不得继续使用旧复盘中的“1–4 年级、5–6 年级”划分。缺失、未知或无法映射的年级单独列入检查结果，不静默丢弃。

### 4.4 商品结构

固定输出：

- 组合品
- 零售品
- 家庭包
- 从小学系列
- 198 价格带
- 498 价格带
- 千元及以上价格带

商品分类必须以项目知识库中确认的商品层级、商品标识或商品规则为准。不同分类允许存在业务上的交叉，但必须在 `指标口径` 表说明其分母和是否互斥；不能用交叉分类相加后与总盘强行对齐。

## 5. 指标清单

### 5.1 经营总览

按私域整体、APP、销售输出：

- 营收
- 去年同期营收
- 营收同比变化额
- 营收同比变化率
- 活动目标
- 目标完成额
- 目标完成率
- 目标差额
- 时间进度
- 营收进度与时间进度差
- 服务期营收
- 业务营收与服务期营收差额

只有私域整体目标时，APP 和销售目标列保留为空，并在口径表标注“未提供渠道目标”，不得自行拆分目标。

### 5.2 活跃效率

按渠道输出整体值，并按用户分层、学段及“用户分层 × 学段”交叉输出：

- 活跃人数
- 付费人数
- 付费金额
- 付费转化率
- 客单价
- ARPU
- 活跃人数占比
- 付费人数占比
- 营收占比

活跃相关指标统一以 C 端活跃主表为分母来源。活跃付费转化率、活跃 ARPU 和活跃口径客单价使用同一活跃人群与同一金额口径，不能混入订单表总营收。

### 5.3 用户分层

对全部固定用户分层，按私域整体、APP、销售输出：

- 活跃人数
- 付费人数
- 付费金额
- 付费转化率
- 客单价
- ARPU
- 活跃占比
- 营收占比
- 组合品付费人数
- 组合品订单量
- 组合品营收
- 组合品转化率
- 组合品客单价
- 组合品 ARPU

### 5.4 学段表现

对 1–3 年级、4–6 年级、初中、高中，按私域整体、APP、销售输出：

- 活跃人数
- 付费人数
- 付费金额
- 付费转化率
- 客单价
- ARPU
- 活跃占比
- 营收占比
- 组合品付费人数
- 组合品订单量
- 组合品营收
- 组合品转化率
- 组合品客单价
- 组合品 ARPU

同时输出“学段 × 用户分层”的同组核心效率指标，便于定位增长或下滑来自哪类人群。

### 5.5 商品结构

对固定商品分类，按私域整体、APP、销售，以及用户分层、学段输出：

- 订单量
- 付费人数
- 营收
- 订单占比
- 付费人数占比
- 营收占比
- 转化率
- 客单价
- ARPU

其中：

- 组合品与零售品需要能够与相同口径的商品大盘校验。
- 家庭包和从小学系列作为专题分类单独展示，不强制与组合品互斥。
- 198、498、千元及以上价格带必须明确价格依据是原价、实付价还是商品标价；第一版以现有复盘已确认口径为准，并在口径表固化。

### 5.6 定金策略

输出来源用户、尾款转化和商品流向，按渠道、用户分层、学段拆分：

- 定金来源用户数
- 定金订单量
- 定金金额
- 尾款人数
- 尾款订单量
- 尾款营收
- 尾款率
- 尾款营收占整体营收比例
- 转组合品人数、订单量、营收
- 转 498 人数、订单量、营收
- 转其他商品人数、订单量、营收
- 未转化人数

定金来源期与尾款观察期是两个独立时间窗口。活动截止日期变化时，只自动延长尾款观察期；不得自动改变定金来源期，除非用户明确提供新的来源期。

### 5.7 蓄水策略

输出来源用户、转化和商品流向，按渠道、用户分层、学段拆分：

- 蓄水来源用户数
- 蓄水订单量
- 蓄水金额
- 转大人数
- 转大订单量
- 转大营收
- 转大率
- 活跃蓄水用户数
- 非活跃蓄水用户数
- 活跃蓄水用户转大率
- 非活跃蓄水用户转大率
- 转化商品流向

蓄水来源期与转大观察期独立处理，规则与定金一致。

### 5.8 高净值策略

对高净值汇总和四类细分，按渠道、学段、商品分类输出：

- 来源用户数
- 活跃人数
- 付费人数
- 订单量
- 营收
- 付费转化率
- 客单价
- ARPU
- 组合品付费人数
- 组合品订单量
- 组合品营收
- 组合品转化率
- 高净值营收占私域营收比例

### 5.9 销售承接

按用户分层、学段输出整体销售漏斗，并分别输出电话与企微链路：

- 线索领取人数
- 线索领取率
- 电话拨打人数
- 有效接通人数
- 有效接通率
- 未有效接通人数
- 企微添加人数
- 企微添加率
- 转化人数
- 转化率
- 转化营收
- 客单价
- ARPU

电话链路还需分别计算：

- 有效接通后的转化人数、转化率、营收、客单价、ARPU
- 未有效接通后的转化人数、转化率、营收、客单价、ARPU

如果企微相关数据库字段不能覆盖完整链路，该指标仍保留在清单中，但必须显示“数据源未接入”，不能由电话或其他触达数据替代。

## 6. 口径与查询组织

### 6.1 固定查询，不依赖自由问答生成

一键数据包使用经过确认和测试的固定查询模板。Codex Skill 只负责收集参数、调用工作流、展示执行状态和返回飞书链接，不在每次运行时临时让模型重新发明 SQL。

### 6.2 查询模块边界

查询按以下独立模块组织：

- 经营总览
- 活跃效率
- 用户分层与学段
- 商品结构
- 定金
- 蓄水
- 高净值
- 销售承接

模块独立执行、独立保存结果和状态。一个模块失败时，不阻断其他模块；最终飞书表格仍生成，并在 `检查结果` 中明确列出失败模块、失败原因和影响的指标。

### 6.3 口径来源

口径优先级：

1. 项目知识库中的最新稳定规则
2. 已被业务确认并能与正文对齐的历史查询
3. 本设计确认后的新增规则

若三者冲突，必须停止受影响模块并报告冲突，不能自行选一个数字继续生成。

## 7. 数据检查规则

### 7.1 运行完整性

- 所有固定模块都有明确状态：成功、失败或不适用。
- 成功模块必须包含本期和去年同期结果。
- 所有结果使用同一组本期、去年同期日期。
- 输出不得混入上一次运行的旧结果。

### 7.2 总分对齐

- 在相同口径下，APP + 销售应与私域整体对齐；允许的差额阈值需在口径表显式配置。
- 用户分层汇总应与对应总盘对齐；未映射用户单列，不可丢弃。
- 1–3 年级、4–6 年级、初中、高中及未知学段之和应与对应总盘对齐。
- 组合品 + 零售品只在两者确实覆盖相同且完整的商品大盘时检查守恒。
- 定金来源人数 = 已转化人数 + 未转化人数，去重口径保持一致。
- 销售领取人数 = 有效接通人数 + 未有效接通人数，仅在两类覆盖完整且互斥时执行。

### 7.3 公式复核

- 转化率 = 付费人数 / 对应人群人数。
- 客单价 = 对应营收 / 对应付费人数或订单量，以指标口径表指定分母为准。
- ARPU = 对应营收 / 对应用户规模。
- 占比类指标的分子、分母必须来自同一日期、渠道和口径。
- 绝对变化 = 本期值 - 去年同期值。
- 相对变化 = 绝对变化 / 去年同期值。
- 目标完成率 = 本期累计营收 / 活动目标。

### 7.4 异常检查

- 缺列、空结果、重复行、重复维度组合。
- 去年同期缺失或天数不一致。
- 百分比超出合理范围。
- 人数、订单量或营收出现不合理负数。
- 同一指标、日期、渠道、维度出现两个不同结果。
- 数据更新时间早于活动截止日期所需分区。

所有检查输出检查项、状态、差额、允许阈值、影响模块和处理建议。检查失败不会被隐藏。

## 8. 飞书表格规则

- 每次运行创建新表，不覆盖原复盘文档或历史数据包。
- `检查结果` 为第一张表，并把失败和警告放在顶部。
- 各业务表的列顺序固定，便于后续自动生成会议材料。
- 数值保留真实数值类型；金额、百分比仅通过显示格式美化，不写成带单位的文本。
- 所有表冻结表头，保持简洁一致的样式。
- `指标口径` 表记录指标名、业务解释、分子、分母、来源表、过滤规则、支持维度和版本。
- `运行记录` 表记录输入参数、执行时间、各模块状态、数据更新时间和结果来源。

## 9. Codex Skill 行为

Skill 在执行时按以下顺序工作：

1. 识别活动名称、开始日期、截止日期和目标。
2. 展示本期与去年同期日期，检查必填参数。
3. 调用固定的一键复盘工作流。
4. 汇总各模块状态并运行一致性检查。
5. 创建飞书表格并写入所有成功结果及检查信息。
6. 回读关键单元格，确认飞书表格写入成功。
7. 在 Codex 中只返回飞书链接、总体检查结果和失败模块，不输出冗长执行细节。

除日期无法推导、目标缺失或口径发生冲突外，Skill 不应要求用户参与中间过程。

## 10. 异常处理

- 数据库查询失败：记录模块、错误和重试建议，继续其他模块。
- 飞书写入失败：保留本地完整结果，不宣称交付成功；修复后重试写入。
- 单表过大：按固定顺序分批写入并回读校验，不截断指标。
- 新枚举或未知分类：进入检查结果，不自动归类。
- 口径冲突：停止受影响模块，列出冲突来源，等待人工选择。
- 数据未更新：标记“数据未刷新”，不得把旧数据写成最新结果。

## 11. 验收标准

### 11.1 功能验收

- 在 Codex 中用一句自然语言可启动完整流程。
- 输入活动名称、日期范围和目标后，不再要求逐项补充指标。
- 一次运行覆盖本设计全部固定模块和指标。
- 所有核心模块同时输出私域整体、APP、销售三套结果。
- 学段固定为 1–3 年级、4–6 年级、初中、高中。
- 用户分层、高净值四类、商品结构、三类策略和销售承接全部保留。
- 自动创建飞书表格并返回可访问链接。

### 11.2 正确性验收

- 本期与去年同期天数完全一致。
- 随机抽取至少 10 个核心指标，与已确认查询结果逐一核对。
- 总分对齐、公式复核和重复冲突检查全部实际运行。
- 故意制造一个模块失败时，其他模块仍正常输出，检查结果能准确说明缺失范围。
- 故意制造总分不一致时，检查结果能展示差额而不是自动修正。
- 飞书写入后回读总览、检查结果和至少两个明细表，数值与本地结果一致。

### 11.3 使用验收

- 用户不需要阅读 SQL 或理解项目目录。
- 最终回复只包含飞书链接、整体检查结论和需要人工处理的问题。
- 同一组输入重复运行时，固定查询和口径版本一致；数据源未变化时结果一致。

## 12. 第一版不包含

- 页面曝光、点击、销售录音、问卷、客服反馈和用户反馈等非数据库素材。
- 自动撰写核心结论、风险判断和动作建议。
- 自动修改或覆盖既有飞书复盘文档。
- 自动选择或调整指标口径。
- 飞书群聊入口、定时任务和异常消息推送。
- 面向其他业务域的通用复盘模板。

## 13. 后续扩展顺序

第一版稳定后，再按以下顺序扩展：

1. 读取本数据包并生成精简会议版飞书文档。
2. 加入页面、录音、问卷和用户反馈等非数据库证据。
3. 根据历史分布和业务阈值生成异常优先级。
4. 接入飞书群聊入口或定时运行。
