# C 端私域关键指标独立看板设计

## 目标

将仓库中现有的“问鼎·C 端私域数据趋势看板”整理为符合 NX 独立报表要求的第一版项目，使其能够按“功能分支 → MR → Preview → 合并发布”的路径上线。

第一版采用快照模式，不改变已经确认的指标口径，不增加浏览器实时查询数仓的能力。

## 项目信息

- 项目编号：`c-end-private-metrics`
- 看板名称：问鼎·C 端私域数据趋势看板
- 正式路径：`/c-end-private-metrics/`
- Preview 路径：`/_preview/c-end-private-metrics/`
- 数据方式：快照
- 访问方式：`login`
- 更新方式：第一版手动更新，不启用定时刷新

## 用户与用途

主要用户是公司内部查看 C 端私域经营情况的业务和管理人员。看板用于快速判断当前经营进度、主要转化环节和需要关注的异常，不承担自由取数或明细查询功能。

## 页面内容

页面沿用现有看板已经确认的指标与结构，至少包含：

- 私域累计营收；
- APP 累计新增流量；
- 定金尾款表现；
- 蓄水用户及转化表现；
- 高净值续费表现；
- 按日趋势；
- 数据截止日期、更新时间和指标口径说明。

桌面端优先保证同屏比较效率，手机端按模块纵向排列，不能出现横向溢出。页面、样式、脚本和数据全部使用相对路径，确保 Preview 与正式路径下都能正常打开。

## 数据流程

1. 现有数据脚本按已确认口径查询和计算指标。
2. 脚本生成脱敏后的快照数据与看板页面。
3. 发布项目只包含页面展示所需的汇总结果，不包含账号、密码、个人信息或订单明细。
4. Preview 展示本次 MR 中的快照。
5. 合并后由发布流程把同一版本上线到正式路径。

浏览器不会连接 StarRocks，也不会获得数据库配置。数据更新需要重新生成快照，并再次经过 MR、Preview 和合并发布。

## 项目组成

独立报表目录包含：

- `monitor.yaml`：项目身份、访问方式、运行方式和 Preview 设置；
- `public/index.html`：看板页面；
- `public/data/`：页面需要的脱敏快照；
- `sql/`：已确认的查询 SQL；
- `docs/metric.md`：指标定义、业务日期、来源与过滤条件；
- `scripts/`：生成快照和页面所需的脚本；
- `tests/`：指标计算、页面产物和发布合同检查。

`monitor.yaml` 保持平台当前要求的 JSON 内容格式，并声明：

- `runtime.type` 为 `static`；
- `auth.mode` 为 `login`；
- `preview.data_mode` 为 `snapshot`；
- `refresh.enabled` 为 `false`；
- Preview 与正式环境使用不同的权限项目编号。

## 异常与边界

- 快照为空时停止生成或发布，不用空数据覆盖上一份正常结果。
- 日期缺失时按现有规则补齐，并明确展示为零或无数据。
- 页面加载失败时显示可理解的提示，不能只留下空白区域。
- 数据截止日期必须在页面醒目展示，避免把旧快照误认为实时数据。
- 不允许把数据库密码、令牌、用户标识、手机号或订单明细写入页面、快照、日志和 Git 历史。
- 第一版不支持任意筛选后重新查询数仓；页面筛选只作用于已加载快照。

## 验收标准

- `monitor.yaml` 可以被正确解析，项目编号、路径和权限编号一致。
- 现有指标计算测试全部通过。
- 页面产物测试通过，所需资源和快照均存在。
- 页面中的核心指标与生成快照一致。
- 电脑和手机显示正常，没有横向溢出。
- Preview 子路径和正式子路径下的资源引用均有效。
- 页面、快照和浏览器请求中不含敏感数据。
- 数据日期、更新时间和口径入口完整展示。
- MR 验收通过后才能合并；生产异常时通过发布流程回滚，不在服务器上手工覆盖文件。

## 本次不做

- 不改变现有指标定义或历史同比规则。
- 不建设实时查询后端。
- 不启用定时任务。
- 不申请项目独占域名。
- 不加入 WOW DATA 门户首页。
- 不把现有仓库中其他取数工具和分析产物打包进独立报表。
